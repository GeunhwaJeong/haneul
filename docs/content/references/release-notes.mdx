# Release Notes

Release notes for Haneul mainnet releases. Full assets and checksums are available on the [GitHub releases page](https://github.com/GeunhwaJeong/haneul/releases).

## mainnet-v1.6.0

**2026-07-31** | [GitHub Release](https://github.com/GeunhwaJeong/haneul/releases/tag/mainnet-v1.6.0)

Haneul mainnet v1.6.0 tracks upstream protocol version 130 as a single-version bump (single-tag-merge pattern). The workspace moves to 1.6.0 and the release ships a new framework module, a reworked RPC index store, and consensus networking refinements.

### Version info

- Workspace version: **1.6.0**
- Protocol version: **121** (activates at the next epoch boundary after the validator upgrade, via capability vote)
- Framework snapshot: `bytecode_snapshot/121`, manifest revision `fc8172ec`

### What's in protocol v121

- Unsettled object-funds withdraws are recorded as **per-account net amounts** from transaction effects instead of running-max amounts, so withdraws offset by deposits in the same transaction no longer block other withdraws from the same account within a consensus commit
- **`init` on upgrade**: init functions of newly introduced modules run during package upgrade
- New **`haneul::scratch`** per-transaction ephemeral store in the framework, with its native gas costs
- Epoch close deadline failsafe for deferred transactions (120s)
- zklogin v2 circuit verification enabled on devnet only; mainnet and testnet behavior is unchanged
- Protocol config snapshots 1-120 remain byte-identical to the previous release

### Node / RPC / CLI

- **New RPC store for gRPC indexes**: on first startup the fullnode performs a one-time, resumable reindex of its RPC index database. Live-object reindexing briefly delays HTTP availability, then historical indexing continues in the background. Plan the deployment window accordingly
- New filtered List APIs are stabilized and filtered subscription APIs are added for checkpoints, transactions, and events
- Opt-in `grpc_request` tracing target captures decoded gRPC request payloads (unset by default)
- Validators automatically recover from checkpoint and transaction forks on restart when the network has certified the canonical outcome and a new binary version is deployed; other forks halt the node awaiting intervention
- The `admission-queue-bypass-fraction` validator config field is removed; all transactions go through the gas-price priority queue (the field is ignored if still present, but should be deleted)
- New address prober on validators periodically checks trusted peers' advertised addresses and reports connectability metrics
- Indexing pipelines are grouped into cohorts by distance from the tip, so a lagging pipeline no longer throttles caught-up ones
- `haneul client chain-identifier` now displays both Base58 and Hex formats; `Move.toml` `[environments]` accepts either format

### Dependencies

- RPC SDK pin advanced to `c20c2214` (frozen lineage; regenerated proto descriptors verified clean)
- `anemo` pin advanced to `68adc31d`, `fastcrypto` pin advanced to `3273734b`
- `haneul-http` stays an in-repo crate, synchronized with the externalized upstream 0.3.1 sources, including the new middleware module (gRPC timeout and callback layers) now used by consensus networking

### Preserved local changes

- Node telemetry removal, self-hosted checkpoint archive tooling, registered coin type 8282 derivation paths, restricted zkLogin OIDC provider set (re-applied over the upstream defaults), name-service mainnet config, chain identifiers, and bridge configuration
- Pinned zkLogin test fixtures keep their upstream iss/kid strings: they are byte-bound to the base64 JWT headers inside the pinned proofs and cannot be renamed without regenerating the proofs

### Verification

- `cargo check --workspace --all-targets` clean; `cargo xclippy` clean; dual `cargo deny check advisories` green
- `cargo simtest -p haneul-e2e-tests`: **454 passed / 0 failed / 24 skipped**
- Shell tests: **83/83** after re-recording build-output ordering drift
- Localnet regenesis on the release build: protocolVersion 121 with the new feature flags active, faucet and 50 HANEUL transfer confirmed end-to-end
- Full diff against the previous release audited: the file set matches the upstream change list exactly and frozen snapshots are untouched
- CI green on the merged PR and on main

### Operational notes

- Standard binary swap on deploy; protocol 121 activates at the next epoch boundary after the validator restarts with capability support
- First fullnode startup on this release rebuilds the RPC index database once (resumable); expect an HTTP availability delay during live-object reindexing and record the observed duration
- Delete `admission-queue-bypass-fraction` from the validator config if present
- The `upgrade/v1.76.1` branch must be preserved (framework snapshot revision reachability)

## mainnet-v1.5.1

**2026-07-30** | [GitHub Release](https://github.com/GeunhwaJeong/haneul/releases/tag/mainnet-v1.5.1)

Haneul mainnet v1.5.1 is a maintenance release on the v1.5 line. It ships the fixes merged since v1.5.0 with no protocol version change, so deployment is a plain binary swap with no epoch-boundary activation.

### Version info

- Workspace version: **1.5.1**
- Protocol version: **120** (unchanged from v1.5.0; no capability vote involved)
- Framework snapshot: unchanged (`bytecode_snapshot/120`, manifest revision `60428dfb`)

### Key derivation (#21)

- Key derivation paths now use the registered SLIP-44 coin type **8282** across all three signature schemes (Ed25519 `m/44'/8282'/...`, Secp256k1 `m/54'/8282'/...`, Secp256r1 `m/74'/8282'/...`), including path validation, keytool help text, and test vectors
- Existing keystores hold raw key material and are unaffected. Only new derivations from a mnemonic use the new paths; re-deriving a wallet from a mnemonic created before this change yields different addresses than the old paths did

### zkLogin defaults (#23)

- The default OIDC provider set for mainnet and testnet is narrowed to the four major issuers: Google, Facebook, Twitch, and Apple
- Node JWK fetchers now target 4 issuer endpoints instead of 17; this also removes a permanently failing fetch loop that retried an unreachable issuer every 30 seconds
- The devnet experimental provider list is unchanged (local testing coverage)
- Regenerated the network config snapshot that serializes this list, and repaired two genesis config snapshots that had drifted from the current protocol version

### Name service (#24)

- The mainnet name-service config now points at the deployed registry objects (package, registry table, reverse-registry table), restoring name resolution across JSON-RPC, gRPC, and GraphQL; these APIs previously queried nonexistent object ids and returned empty results
- `examples/prod-config/graphql.toml` synchronized to the same ids
- Reverse (address to name) records populate as name owners opt in via `set_reverse_lookup`; an empty reverse result for a registered name is expected until then
- The testnet config is intentionally untouched (no deployment to point at yet)

### CI (#22)

- Unit tests for the core crates now run on every pull request alongside the existing lint checks

### Test hygiene (#25)

- Shell-test fixtures updated to the current chain id, and 24 snapshots re-recorded after build-output ordering drift from the previous upgrade (content identical); suite green at 83/83

### Version string (#26)

- Workspace version bumped to 1.5.1 so released binaries report themselves as `haneul 1.5.1-<commit>`

### Verification

- Per-change test runs: haneul-config 15/15, haneul-swarm-config 7/7, haneul-name-service 6/6, shell tests 83/83 (two consecutive green runs), haneul-open-rpc 2/2 including the spec/version match test
- `cargo xclippy` clean on every change; CI green on all merged PRs

### Operational notes

- Standard binary swap on deploy; protocol version is unchanged, so nodes restart directly on the new binary with no activation step
- Post-deploy checks: the 30-second JWK retry warnings disappear from the node journal, and `haneulx_resolveNameServiceAddress` on a registered name returns its address

## mainnet-v1.5.0

**2026-07-17** | [GitHub Release](https://github.com/GeunhwaJeong/haneul/releases/tag/mainnet-v1.5.0)

Haneul mainnet v1.5.0 tracks upstream protocol version 129 as a single-version bump (single-tag-merge pattern) and completes a repository-wide naming alignment pass over binary test artifacts.

### Version info

- Workspace version: **1.5.0**
- Protocol version: **120** (activates at the next epoch boundary after the validator upgrade, via capability vote)
- Framework snapshot: `bytecode_snapshot/120`, manifest revision `60428dfb`

### What's in protocol v120

- **Unified linkage in PTBs** (`enable_unified_linkage`) — enabled on all networks
- Framework: `insert_before` / `insert_after` on `haneul::linked_table`; `haneul::coin` now uses `defining_ids`
- Binary pool bounds made explicit
- Protocol config snapshots 1–119 remain byte-identical to the previous release; the v120 delta is the single feature flag

### Node / RPC / CLI

- State-sync archive fallback now supports `gs://` ingestion URLs; a new `remote-store-headers` option under `state-archive-read-config` attaches default HTTP headers to archive requests
- New optional `RUST_LOG_TAILS` env var writes individual tracing targets to dedicated files (also available to indexer binaries); unset by default, no action required
- gRPC/GraphQL scanning APIs (`list_transactions`, `list_events`, `list_checkpoints` and the `Transaction` connection cursor) use a new opaque pagination cursor encoding — restart pagination from the beginning on cursor errors
- GraphQL request payloads can be captured for replay via the `graphql_request` tracing target
- `haneul start` respects the fullnode RPC socket address from its network config

### Dependencies

- RPC SDK pin advanced to `4f0dc46d` (new proto fields on `Event`/`ExecutedTransaction`/`QueryOptions`/`Watermark`, ergonomic v2alpha filter builders, GraphQL schema refresh)
- `tidehunter`/`tideconsole` pin advanced to `4326af7b`
- `crossbeam-epoch` held at 0.9.20 in both workspaces (RUSTSEC-2026-0204); dual `cargo deny check advisories` green

### Naming alignment (#20)

- Decompiler bytecode fixtures: composite identifiers and string constants now follow the same naming rules as the rest of the tree
- Regenerated the consistent-api and fork-service gRPC descriptor sets so reflection advertises the same `haneul.*` service names the servers register
- Trace-adapter debug-info fixtures and unit-test lockfiles aligned with the tree

### Preserved local changes

- Node telemetry removal (#12), external-crates-test 75-minute timeout (#13), mainnet short id test fix (#17), self-hosted checkpoint archive support in formal snapshot restore (#18 — call sites adapted to the new three-argument `build_object_store` signature)

### Verification

- `cargo check --workspace --all-targets` clean; `cargo xclippy` clean; dual `cargo deny` green
- `cargo simtest -p haneul-e2e-tests`: **435 passed / 0 failed / 24 skipped**
- Localnet regenesis on the release tree: protocolVersion 120, `enable_unified_linkage` active, faucet and 50 HANEUL transfer confirmed end-to-end
- CI green on both merged PRs (15 pass / 12 skip / 0 fail each)

### Operational notes

- Standard binary swap on deploy; protocol 120 activates at the next epoch boundary after the validator restarts with capability support
- First upgrade deployment since the checkpoint archive went live: after restart, confirm the snapshot uploader loop line in the node log, checkpoint files accumulating in the ingestion directory, and the next archiver batch upload
- The `upgrade/v1.75.2` and `fix-new` branches must be preserved (framework snapshot revision reachability)

## mainnet-v1.4.0

**2026-07-04** | [GitHub Release](https://github.com/GeunhwaJeong/haneul/releases/tag/mainnet-v1.4.0)

Protocol version 119 release. Consolidates upstream protocol versions 127–128 into a single v119 block, following the same single-tag-merge pattern used for v116–v118.

### Version info

- Workspace version: **1.4.0** (semver bump from 1.3.1)
- Protocol version: **119** (`MAX_PROTOCOL_VERSION`)
- Move execution engine and gas model: unchanged from v117 (`execution_version = 4`, `gas_model_version = 14`)

### What's in v119

### Epoch close & consensus (from upstream v127)

- `timestamp_based_epoch_close` — **now enabled on mainnet** (was devnet/testnet/local only in v118). Epoch boundaries are determined by timestamps instead of commit counts, structurally removing the class of emergency forced-epoch-close interventions.
- `always_advance_dkg_to_resolution` — DKG always advances to the resolution phase.

### Cryptography gas prices (from upstream v127)

- `verify_bulletproofs_ristretto255_base_cost`: 30,000 → **23,866**
- `verify_bulletproofs_ristretto255_cost_per_bit_and_commitment`: 6,500 → **1,324**
- `group_ops_ristretto_*` costs introduced (decode scalar/point 5/216, add/sub 2/8, mul 5/1763, div 557/2244)
- `enable_ristretto255_group_ops` / `enable_verify_bulletproofs_ristretto255` — devnet/testnet/local only; **disabled on mainnet**

### Binary table bounds (from upstream v128)

Bounds that were previously only implicitly constrained are now explicit:

- `max_generic_instantiation_type_nodes_per_function = 10,000`
- `max_generic_instantiation_type_nodes_per_module = 500,000`
- `binary_enum_defs = 200`
- `binary_enum_def_instantiations = 100`

### Node, RPC & CLI

- Node reliably reports and disconnects state-sync peers that are consistently unreachable.
- Fixed a spurious panic that could occur during a normal node shutdown/restart (randomness receiver channel).
- New `haneul-rpc-store` and `haneul-consistent-store` crates; the fullnode can embed the rpc-store behind a config flag.
- `SimulateTransaction` now accepts `gas_price=0` for gasless-tier-eligible transactions instead of returning an error.
- CLI: adds `haneul move lint`; renames `--forking-mode` to `--skip-signing`.

### Dependencies

- `haneul-rust-sdk` bumped to `ebce2053` (transaction predicate filters, package write RPC support; regenerated proto descriptors). Pushed as a fast-forward on top of the previous revision, so all previously pinned revisions remain reachable.
- `anemo` bumped to `b1bda3f8`, `fastcrypto` bumped to `c6010b90` (forks synced).
- `tokio-postgres`: 0.7.12 → 0.7.18 (resolves RUSTSEC-2026-0178 DataRow panic DoS)
- `deny.toml`: quick-xml ignores retained with reachability justification (RUSTSEC-2026-0194 / -0195, object_store-only path); the diesel-async ignore was dropped — the 0.9 migration is now inherited.

### Move test artifacts regenerated

- `move-compiler` snapshots: linter, expansion, one-time-witness, and `ide_mode` fixtures — diagnostic span columns and in-scope address ordering
- `move-package`: `nested_deps_git_local` resolver-error capture and `parsing_flavor` manifest digest
- `move-decompiler`: `kiosk_bidding_house` fixtures — the `.mv` inputs already aligned with the Haneul framework in v118 were preserved as-is; decompiler outputs regenerated for the refined decompiler
- Protocol config snapshots regenerated: versions 1–118 verified byte-identical to the released configs; v119 added

### Verification

- `cargo check --workspace --all-targets` / `cargo xclippy` / `cargo deny check` (root + `external-crates/move`): all clean
- Local network boot reports `protocolVersion: 119`
- Faucet → new wallet → `transfer-haneul` executed successfully (Status: Success)
- End-to-end simulation tests: **432 passed / 0 failed / 24 skipped**
- Move package publish E2E on a v119 local network: `haneul move build` resolves implicit framework dependencies and `haneul client publish` succeeds (Status: Success)

### Operational notes

- Deploy with the standard mainnet upgrade procedure (binary swap; no `--force-regenesis`; existing chain data preserved). v119 activates automatically at the next epoch boundary after a validator quorum reports support.
- After activation, epoch close on mainnet switches to timestamp-based scheduling. No operator action required.
- The node telemetry removal (#12) and the 75-minute external-crates-test CI timeout (#13) are preserved in this release.
