Haneul is a scalable and performant layer-1 blockchain that is home to a complete stack of native primitives ideal for building decentralized applications. Such primitives, such as those for [encryption](https://seal-docs.wal.app/UsingSeal/), [data storage](https://docs.wal.app/usage/setup), verification, and access control, provide developers with every piece of the application stack without needing to use layer-2 chains or offchain solutions. 

In contrast to other chains, Haneul uses an [object-centric model](/develop/haneul-architecture/object-model), where every item on the network is an object. [Transactions](/develop/transactions/txn-overview) use objects as input, which mutate an existing object or create new objects. Each object has a unique onchain ID.

To create objects, submit transactions, and start building an application on Haneul, first you must install Haneul. This installation includes the [Haneul CLI](/references/cli), a tool that creates and manages address balances, builds and publishes smart contracts, and queries information from the network.

## Quick install 

You use the Haneul CLI to interact with the Haneul network, deploy packages, and manage assets. To install the Haneul CLI, you can use [`haneulup`](https://github.com/GeunhwaJeong/haneulup).

[`haneulup`](https://github.com/GeunhwaJeong/haneulup) is the most effective installation method, as it allows you to easily install and switch between different versions of not only the Haneul CLI but also other Haneul stack components like [`walrus`](https://docs.wal.app/usage/setup) and [`mvr`](https://github.com/GeunhwaJeong/mvr). 

Alternative quick install instructions for [Homebrew](https://brew.sh/) or [Chocolately](https://chocolatey.org/) do not support installing other Haneul stack components. You need to install other components through their individual binaries if you'd like to use them in the future. 

:::caution 

Installations using Homebrew or Chocolatey might take several minutes if you do not have any of the [Haneul prerequisites](/getting-started/onboarding/install-source) installed. Using `haneulup` is often much faster and highly recommended.

:::

<ImportContent source="quick-install" mode="snippet" />

The quick install is suitable for most use cases. For those wanting more control over the installation process, you can [install from source](/getting-started/onboarding/install-source) or [install binaries](/getting-started/onboarding/install-binaries).

If Haneul is already installed from a previous development environment, be sure to upgrade to the [latest version](/getting-started/onboarding/install-binaries).

### Verify the installation

After installing, open a new terminal and run:

```sh
$ haneul --version
```

If the installation succeeded, the command prints the installed Haneul version.

## Installation details 

### `haneulup` installation details 

Refer to the `haneulup` repository's [README](https://github.com/GeunhwaJeong/haneulup?tab=readme-ov-file#paths-used-by-the-haneulup-tool) for information regarding installation files and their locations. 


### Default configuration file

Regardless of whether you used `haneulup`, Homebrew, or Chocolately, Haneul stores a primary configuration in the `~/.haneul/haneul_config/client.yaml` file. This file defines settings and preferences for your environment, such as:

- Network environment details for Mainnet, Testnet, Devnet, and Localnet networks.

- Active environment, which specifies the network the CLI commands target.

- Active address, which specifies the Haneul address the CLI uses for transactions and queries.

- Keystore location, which specifies where Haneul stores your address' private keys.
