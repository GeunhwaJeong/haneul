A [Programmable Transaction Block](/develop/transactions/ptbs/prog-txn-blocks) (PTB) groups several onchain actions into a single transaction that succeeds or fails as a unit. Send one from an app you already have, whether it signs with its own key pair or relies on a user's wallet.

:::tip

The sections below cover the integration points, not the full API. For complete coverage of transaction building, including inputs, commands, results, and execution, see [Haneul Programmable Transaction Basics](https://sdk.haneul-labs.com/typescript/transaction-building/basics) in the TypeScript SDK documentation.

:::

## Configure your project for ES modules

The Haneul TypeScript SDK ships as an ES module, so your project's TypeScript configuration has to resolve ES modules. In a Node.js backend, that means `module` and `moduleResolution` settings such as `NodeNext`:

```json title='tsconfig.json'
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "skipLibCheck": true
  }
}
```

Frontend build tools such as Vite and Next.js handle this for you. If you do not have a frontend project yet, the dApp Kit starter scaffolds one with the configuration already in place:

```bash
$ npm create @haneullabs/dapp
```

## Send a transaction from a backend script

A backend script signs with a key pair that you control. Load the secret key from an environment variable, never from a hardcoded string.

Install the core SDK package:

```bash
$ npm install @haneullabs/haneul
```

The following script builds a transaction that sends 0.1 HANEUL to a recipient, signs it, executes it, and checks the result:

```ts title='send.ts'
import { Ed25519Keypair } from '@haneullabs/haneul/keypairs/ed25519';
import { HaneulGrpcClient } from '@haneullabs/haneul/grpc';
import { Transaction } from '@haneullabs/haneul/transactions';
import { GEUNHWA_PER_HANEUL } from '@haneullabs/haneul/utils';

const client = new HaneulGrpcClient({
  network: 'devnet',
  baseUrl: 'https://fullnode.devnet.haneul.io:443',
});

// Load the secret key from the environment, never hardcode it.
const keypair = Ed25519Keypair.fromSecretKey(process.env.HANEUL_SECRET_KEY!);

// Build a transaction that sends 0.1 HANEUL to a recipient.
const tx = new Transaction();
tx.transferObjects([tx.coin({ balance: 0.1 * Number(GEUNHWA_PER_HANEUL) })], '0xRecipientAddress');

const result = await keypair.signAndExecuteTransaction({ transaction: tx, client });

if (result.$kind === 'FailedTransaction') {
  throw new Error(`Transaction failed: ${result.FailedTransaction.status.error?.message}`);
}

console.log('Transaction digest:', result.Transaction.digest);
```

The `tx.coin` method sources the requested amount from your address balance when available and falls back to owned coins, so you do not need to pick coins yourself. The `transferObjects` command then sends that coin to the recipient.

Always check the `$kind` field on the result. A transaction can be submitted and still fail onchain, so treat a `FailedTransaction` result as an error rather than assuming success.

## Send a transaction from a frontend wallet

A frontend app does not hold the user's key. The user's wallet signs the transaction through Haneul dApp Kit, so your code only builds the transaction and hands it to the wallet.

Install dApp Kit alongside the core SDK:

```bash
$ npm install @haneullabs/dapp-kit-react @haneullabs/haneul
```

This example assumes a `DAppKitProvider` wraps your app, configured with `createDAppKit`. For the provider setup, see [Getting started with dApp Kit for React](https://sdk.haneul-labs.com/dapp-kit/getting-started/react).

The following component builds the transaction in the click handler and asks the connected wallet to sign and execute it:

```tsx title='SendButton.tsx'
import { ConnectButton } from '@haneullabs/dapp-kit-react/ui';
import { useCurrentAccount, useDAppKit } from '@haneullabs/dapp-kit-react';
import { Transaction } from '@haneullabs/haneul/transactions';
import { GEUNHWA_PER_HANEUL } from '@haneullabs/haneul/utils';

export function SendButton() {
  const account = useCurrentAccount();
  const dAppKit = useDAppKit();

  async function handleSend() {
    if (!account) return;

    // Build a transaction that sends 0.1 HANEUL to the connected account.
    const tx = new Transaction();
    tx.transferObjects([tx.coin({ balance: 0.1 * Number(GEUNHWA_PER_HANEUL) })], account.address);

    const result = await dAppKit.signAndExecuteTransaction({ transaction: tx });

    if (result.$kind === 'FailedTransaction') {
      console.error(result.FailedTransaction.status.error?.message);
      return;
    }

    console.log('Transaction digest:', result.Transaction.digest);
  }

  return (
    <div>
      <ConnectButton />
      {account && <button onClick={handleSend}>Send</button>}
    </div>
  );
}
```

Pass the `Transaction` instance directly to the wallet. The wallet sets the sender, selects gas coins, and signs, so you never call `tx.build()` yourself and never touch the user's key.

:::danger

Never include a secret key or recovery phrase in frontend code. Anything you ship to the browser is public, so a key in frontend code is exposed to everyone who loads the page. In a frontend app, the user's wallet signs the transaction, which means your code never handles their key. Keep secret keys in backend scripts only, and load them from environment variables or a secret manager.

:::
